\begin{abstract}
Modeling tools use metamodels to specify which elements and relationships a
model may contain. Essential MOF (EMOF) supplies common constructs for these
specifications, but implementing its rules requires reconciling requirements
spread across the standard. Different interpretations can lead tools to disagree
on whether a model is valid. We define structural EMOF conformance for finite
models in Lean, a proof assistant that checks mathematical proofs. The definitions
cover inheritance, property values, multiplicity, opposites and containment.
We prove that our executable checker accepts exactly the models satisfying
these definitions. We also give named model declarations a meaning independent
of the checker and prove that translation to its internal representation preserves
that meaning under explicit naming conditions. A railway model from the Train
Benchmark exercises translation and validation using the complete adapted
structural metamodel. Comparisons with the Eclipse
Modeling Framework (EMF) show why both validation decisions and the values loaded
by each tool must be examined. Controlled workloads expose scalability limits
for deeply nested containment. The result provides common definitions for
checking and reasoning about models, while standards interpretation and file
parsing and interchange remain outside the machine-checked guarantees.
\keywords{EMOF \and Metamodeling \and Formal semantics \and Model conformance \and Mechanized verification}
\end{abstract}
