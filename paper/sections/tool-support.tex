\section{Tool Support}
\subsection{Implementation and Verification}
VL-MOF\footnote{\url{https://github.com/SEhumantics/VLMOF} (review access pending)} implements the definitions and verified functions of Section~3 in Lean.
Its CLI accepts symbolic declarations or Core JSON, invokes the snapshot checker,
and distinguishes parsing, binding, decoding and conformance failures.

Figure~\ref{fig:boundary} follows text through parsing and elaboration to the
Core pair and its checker. The export experiment writes Ecore/XMI and loads it
in EMF, then checks both EMF acceptance and preservation of objects and property
values. Observation comparison therefore receives the initial Core state and
the loaded EMF state. Parsing, JSON conversion and the bridge are tested
components outside the checker and AST-elaboration proofs.

\subsection{Textual Notation}
The DSL provides a readable notation for schemas and snapshots used by the
checker and elaborator. Qualified aliases
select declarations, \texttt{@} denotes an object reference, and
\texttt{observe} supplies a property's values. A route excerpt is:
\par\noindent\begin{minipage}{\linewidth}\small
\begin{verbatim}
object o1 : railway::Route {
  observe railway::Route::active = [true];
  observe railway::Route::requires =
    [@o25, @o26, @o27, @o28, @o29, @o30, @o31];
}
\end{verbatim}
\end{minipage}\par
Scalars use singleton lists; $[]$ records absence or an empty collection.
Applicable rows and paired opposite ends must be explicit. The complete input
also supplies the inherited \emph{id}, entry/exit and follows rows, referenced
objects and declarations; this excerpt alone is incomplete.

\subsection{EMF Interchange}
The Java bridge loads Ecore/XMI through dynamic EMF for comparison. Its declared
profile rejects unsupported features, including annotations, operations and
general default/unset features. Export requires class-owned ends, representable
names and packages, and signed 32-bit integers, whereas Lean also supports
association-owned ends and unbounded integers. The artifact specifies the profile.

Import allocates identities from containment and distinguishes written scalar
values from omissions. This can differ from \texttt{eIsSet}, especially for an
explicit first enumeration literal. Export establishes both opposites in fresh
resources. A sidecar maps Core identities to native URIs; observation comparison
uses that bijection, ordered sequences and unordered multisets. Agreement is
checked for each input rather than inferred from equal validation results.
