\subsection{Implementation and Verification}
VL-MOF\footnote{\url{https://github.com/SEhumantics/VLMOF}} parses text into
source documents, elaborates them into Core pairs and checks these; Core JSON is decoded
directly. Theorems~\ref{thm:checker} and~\ref{thm:adequacy} are mechanized in
Lean. Lean's definition of conformance computes ancestors, package nesting
and parent chains by the checker's breadth-first search, and separate lemmas prove
that, when references resolve, this search finds exactly the chains of
Section~\ref{sec:formalization}. Theorem~\ref{thm:checker} then follows mainly by
expanding both side by side.
Theorem~\ref{thm:adequacy} is proved about the executable elaborator itself:
lemmas trace each Core declaration, object and row back to its source, and show
that distinct names receive distinct numbers and that each Core lookup is the
renamed source lookup. It also uses the search lemmas, since $\mathcal S(d)$ is
defined with chains, so $\mathcal S(d)\Leftrightarrow\operatorname{check}(S,M)=\mathsf{true}$
in Eq.~\eqref{eq:adequacy} is mechanized against a definition free of the
checker's search. Parsing and decoding,
including the lexical admissibility of parsed names, are tested, not proved.
Lean proofs use propositional extensionality, choice and quotient soundness;
execution also trusts the compiler and runtime.

\paragraph{Textual notation.}
Source documents (Definition~\ref{def:document}) are written in a textual notation.
Figure~\ref{fig:notation} pairs an object grammar fragment with the object $r$ of
$M_T$, omitting package prefixes. Here \texttt{?} means optional, \texttt{*}
repetition, and \texttt{qname} a name qualified with \texttt{::}; values include
literals and \texttt{@} object references. Every applicable observation is
explicit: scalars use singleton lists, and \texttt{[]} records an empty sequence,
as for \emph{entry} and \emph{exit}.

\subsection{EMF Interchange}
VL-MOF can also check models stored by EMF. A Java bridge reads an \texttt{.ecore}
metamodel and its \texttt{.xmi} instances, converts their declarations and object
values into Core JSON, and passes that representation to the Lean checker.
The bridge assigns object identities and preserves explicitly written values
and omissions. EMF's \texttt{eIsSet} may instead treat an explicit default value
as unset, so equal validator decisions need not mean equal loaded models.
The comparison maps identities and checks classifiers, values and selected
metadata, preserving sequence order or comparing multisets as appropriate.
Figure~\ref{fig:boundary} shows the Ecore/XMI import experiment. Decision boxes
compare validator outcomes; collected observations compare loaded property values.

Import and export cover only the artifact's structural subset, excluding
annotations, operations and general default/unset behavior; round-trip tests
reimport exported files and recheck conformance.
