\section{Tool Support}
\subsection{Implementation and proof boundary}
The Lean library exposes raw records, structural predicates, finite checks and
reusable theorems. Its CLI accepts symbolic text and versioned Core JSON, with
separate parse, bind, decode, unsupported-input and conformance outcomes.
Figure~\ref{fig:boundary} separates proved checking from the tested export/reload
comparison loop. The companion archive \texttt{vlmof-companion.tar.gz} includes
the source, clause ledger, retained runs and a result-recomputation guide.

\subsection{Authoring notation and its costs}
The explicit language supports inspection and malformed-state diagnosis.
Qualified aliases select inherited declarations; \texttt{@} denotes an object
reference; \texttt{observe} records occurrences. Scalars use singleton lists;
\texttt{[]} is zero occurrences (optional scalar/reference absence or an empty
multivalued collection), while a missing row violates coverage. These are
interface choices, not EMOF syntax. The running example contains:
\par\noindent\begin{minipage}{\linewidth}\small
\begin{verbatim}
object route : railway::Route {
  observe railway::RailwayElement::id = [101];
  observe railway::Route::active = [true];
  observe railway::Route::follows = [@switchPosition];
  observe railway::Route::requires = [@sensorA, @sensorB];
}
\end{verbatim}
\end{minipage}\par
The complete file includes declarations, other objects and inverse rows.
Paired inconsistency yields an opposite-count diagnostic; missing sensors yield a
multiplicity diagnostic. No inverse repair or duplicate removal is implicit.

Concise sugar and Emfatic are alternatives \cite{emfatic_docs}. Short names and
scalar assignments need ambiguity, omission and inverse-conflict rules, so that
sugar remains unimplemented. Emfatic supports containment/opposites but can
exceed the native profile and has no proved AST boundary. There is no measured
productivity advantage; persistent identity and default/unset need migration.

\subsection{EMF interchange and metadata clients}
The Java bridge loads Ecore/XMI through dynamic EMF. Its profile rejects
annotations, operations, generics, declared defaults, derived/unsettable features,
custom datatypes and unresolved references. Export requires class-owned ends,
representable packages/names and signed 32-bit integers.

Import allocates identities from containment and tracks written scalars separately
from omissions. This can differ from \texttt{eIsSet}, especially for an explicit
first enum literal; declared defaults remain unsupported. Export establishes both
opposites in fresh resources. Its sidecar maps Core IDs to native URIs; comparison
uses that bijection and ordered sequences or unordered multisets. Thus lossless
alignment is checked per input, not inferred from acceptance.

A metadata client interprets ordinary objects for concrete root classes and finite
scalar attributes as a schema, then checks it. A dangling owner fails typing;
reversed bounds can pass typing yet fail schema validity. Packages, inheritance,
references and full self-description remain outside the pilot.
