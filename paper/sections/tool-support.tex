\section{Tool Support}
\subsection{One checker, three input routes}
The Lean library has no external mathematics dependency. Its command-line tool
accepts the symbolic language and a versioned JSON representation; both routes
end at the same Core checker. Reports distinguish accepted models, rejected
represented models, binding or decoding errors, unsupported interchange
versions, and file errors. The catalog listing supplied with the paper is
accepted through the symbolic route.

Figure~\ref{fig:boundary} locates the proved and tested connections. Parsing is
outside Equation~\ref{eq:adequacy}, which begins at the source AST. The JSON
decoder can represent malformed Core records so that the complete checker, not
the decoder, decides conformance. Unknown object fields are ignored and duplicate
JSON keys follow the parser's normalization policy; these are documented wire
policies rather than consequences of Equation~\ref{eq:checker}.

\subsection{Restricted EMF realization}
The Java bridge loads real Ecore and XMI resources with EMF dynamic objects. It
accepts only the native subset it can translate without discarding meaning.
Unsupported annotations, operations, generics, defaults, derived or unsettable
features, custom datatypes, and unresolved references are rejected. Ecore export
also requires class-owned association ends, representable package structure and
names, and signed 32-bit integers, a smaller domain than Core's integers.

Import allocates declaration identities from metamodel containment and object
identities from instance containment. A structural XML pass records whether a
scalar was written, so an omitted optional value remains different from an
explicit default value. It validates the correspondence between XML elements and
loaded objects before producing one observation row for each applicable
property.

Export constructs fresh metamodel and instance resources. It sets both opposite
pointers, allocates all objects before references, and compares the resulting
observations with the requested Core snapshot before serialization. A sidecar
relates Core identities to native URIs. On reload, the comparator requires this
map to be a bijection over declarations and objects, remaps references, and
compares each sequence or multiset according to the property's ordering flag.
This experiment tests a concrete realization of the formal observations; the
adapter and EMF runtime remain outside the Lean proof.

\subsection{Reuse for bounded metadata}
A fixed metadata vocabulary represents class and scalar-attribute descriptions
as ordinary objects and properties. The common checker validates a description
before an interpreter produces a Core schema. The example describes an optional
Boolean property and then checks an instance of the resulting class. A dangling
owner is rejected as metadata; reversed bounds can be well-typed metadata yet
produce an invalid interpreted schema. This separates validity of the
description graph from validity of what it denotes.
