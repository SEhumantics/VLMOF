\subsection{Textual notation}
The DSL provides an input notation for exercising the formal semantics. It is
not a new EMOF semantics or an official EMOF concrete syntax. Qualified aliases
select declarations, \texttt{@} denotes an object reference, and
\texttt{observe} supplies a property's values. For example:
\par\noindent\begin{minipage}{\linewidth}\small
\begin{verbatim}
object route : railway::Route {
  observe railway::RailwayElement::id = [101];
  observe railway::Route::active = [true];
  observe railway::Route::follows = [@switchPosition];
  observe railway::Route::requires = [@sensorA, @sensorB];
}
\end{verbatim}
\end{minipage}\par
Scalars use singleton lists. An empty list records absence of an optional value
or an empty collection; an omitted applicable row is invalid. Opposite ends are
written explicitly so the checker can detect inconsistent links instead of
repairing them. The complete example also declares the schema, other objects
and reverse observations.

Explicit names and paired observations aid inspection but require verbose edits.
Emfatic and Xcore are established alternatives \cite{emfatic_docs,xcore_docs}.
A shorter front end needs omission, binding and inverse-conflict rules; authoring
productivity has not been measured.

\subsection{EMF interchange and metadata}
The Java bridge loads Ecore/XMI through dynamic EMF. Its supported profile
excludes annotations, operations, generics, declared defaults, derived/unsettable
features, custom datatypes and unresolved references. Export requires
class-owned ends, representable packages and names, and signed 32-bit integers.

Import allocates identities from containment and distinguishes written scalar
values from omissions. This can differ from \texttt{eIsSet}, especially for an
explicit first enumeration literal. Export establishes both opposites in fresh
resources. A sidecar maps Core identities to native URIs; observation comparison
uses that bijection, ordered sequences and unordered multisets. Agreement is
checked for each input rather than inferred from equal validation results.

A small metadata interpreter reads ordinary objects describing concrete root
classes and scalar attributes, constructs a schema, and checks it. A dangling
owner fails typing; reversed bounds can pass typing yet fail schema validity.
Packages, inheritance, references and full self-description are not supported
by this interpreter.
