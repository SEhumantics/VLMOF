\subsection{Cases and Proof Reuse}
We use public Train models and authored containment/inheritance cases; the
bridge rejects unchanged EMF Compare input as unsupported. Train is the only
public positive family. The artifact records inputs, licenses, adaptations and commands.

Checked examples distinguish the interpretations in
Table~\ref{tab:source-findings}: structural versus creation bounds, parent versus
container-role identity, and inherited declaration identity. Default and operation
discrepancies remain source findings outside the implemented fragment.

\paragraph{RQ2: Proved properties.}
The Lean build checks the decision and source theorems. The opposite-count

The Boolean-edit client composes Equation~\ref{eq:toggle} with checker equivalence

\subsection{Comparison with EMF}
The comparison pins EMF Ecore/XMI 2.39.0 and Common 2.42.0 under Java~21.
An isolated registry selects EcoreValidator for schemas and generic
EObjectValidator for dynamic instances. Diagnostician validates schema and
instance roots separately. Generated validators and OCL delegates are outside
this condition. Table~\ref{tab:correctness} reports fresh outcomes, including
instance calls on schemas that Ecore rejects. A and R denote accept and reject;
S and I denote schema and instance-root calls. An accepted instance call does not
override schema rejection. Alignment compares mapped identities, classifiers and
observations, not general schema equivalence.

The zero-upper and nonunique-containment rows expose Ecore schema restrictions.
The repeated unique String survives loading but is accepted by this generic
validator and rejected by VL-MOF; it does not establish the behavior of every
EMF editor or generated validator. Repeated traversal of a contained object
produces duplicate collector rows in the two unpaired cases. Their alignment is
conservatively unsuccessful even though their distinct URI/value comparisons
agree; they are not timed.

Alignment also checks featureless objects and bijective declaration provenance.
A primitive-type/tag gate replayed on all 63 retained pairs changed no decisions;
this does not prove adapter correctness or schema equivalence.

The full optional-bound Train v1.0 profile retains ten classes, 21 features and two
enumerations, after removing a generator annotation and mapping three
primitive types. Its bounds differ from the published diagram (Section~2).
The adapted batch-1 snapshot has 754 objects and 3,378 observations:
twelve explicitly written first-enumeration values are reported unset by native
\texttt{eIsSet}, while the lexical Core route retains \texttt{FAILURE}.
Both systems accept their respective states. This input had materialized twelve
omitted defaults and stays excluded from paired timing. A fresh control using
untouched original batch-1 XMI and the explicitly adapted Ecore profile is accepted
by both validators and aligns. Zero lower bounds permit its omissions; preserving
them resolves this comparison without inserting defaults. This does not establish
general default/unset equivalence. The unadapted generated schema remains an
unsupported annotation boundary.

The companion's \texttt{full-v1-batch-1.dsl} supplies this complete schema and
instance, with a declaration crosswalk. Actual parsing/elaboration reproduces
the retained Core pair exactly, including IDs, flags, row order and absence;
this tests correspondence, not converter correctness. Route 1 follows position 2,
requires sensors 25--31 and has entry/exit semaphores 425/34. Toggling its present
\emph{active} value preserves acceptance; retaining only one sensor fails
multiplicity alone. This adds notation coverage and a preservation client,
not native or timing measurements.

\subsection{Validation Time}
The timing cases use the authored optional-bound Train projection, not the full
public snapshot. The deterministic workload has stars with inherited scalar features and
ordered occurrences (11/101/501 objects), Train groups (10/100/500), and
containment chains (11/101/501, depths 10/100/500), with fixed schema vocabulary.
Declaration, inheritance, observation and reference counts accompany object count.

Five independent process trials use ten warmups and thirty measured repetitions.
Each fixed case receives both tool orders, with reversed traversal on alternate
trials. Builds finish before timing. The primary window is preloaded combined
schema/instance validation; diagnostics, loading and serialization are excluded.
Schema-only, read/decode and command-wall times are recorded separately.
Registry-only and instance-only timing were not run; subtracting schema time
would not measure the latter.
