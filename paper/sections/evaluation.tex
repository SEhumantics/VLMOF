\section{Evaluation}
\subsection{Evidence design}
The evaluation asks different evidence to support different claims. Kernel
checking supports the universal formal statements. Authored fixtures exercise
representation boundaries and diagnostic behavior. Native round trips test the
trusted adapter on fixed inputs. Timings describe those runs only. The artifact
runner records commands, input hashes, outcomes, and whether a stage was
accepted, rejected, unsupported, not run, or failed to execute.

The proof build checks the conformance decision, reachability, source
preservation and reflection, and the metadata consequence. A separate client
uses the library to derive that two conforming rows with the same object/property
key have equal occurrence lists. Ten authored regression cases cover acceptance,
absence, type errors, duplicates, unresolved binding, malformed records, and an
unsupported wire version. The complete catalog source in this paper was also
run through the symbolic command and accepted. These examples exercise code
paths; the universal evidence is the proof of Equations~\ref{eq:checker} and
\ref{eq:adequacy}.

The companion archive is named \path{VL-MOF-artifact.zip}. Its top-level
instructions map mathematical concepts in the paper to declarations, give the
reproduction commands, and describe the trust boundary. Machine-readable
manifests contain source revisions and hashes.

\subsection{Public inputs and explicit adaptation}
The public study uses six XMI snapshots from Train Benchmark
\cite{szarnyas_etal_2018}. They share one
Xcore metamodel and therefore form six instances of one language, not six
independent compatibility cases. The original project does not provide a
checked-in Ecore file for this route. A pinned Xcore compiler produces an
intermediate Ecore with generic Java-object mappings for three primitives and a
generator annotation that the bridge rejects. The evaluated adapted metamodel
removes that annotation and maps the three properties to EInt or EBoolean, as
declared in the original Xcore. The manifest records each change and retains the
original inputs.

Some native snapshots omit enumeration values interpreted by their originating
runtime as a default literal. Separate adapted copies materialize those values;
Table~\ref{tab:train} reports the number inserted. A raw batch-1 control is also
accepted because the corresponding properties are optional in the selected
profile. Materialization therefore changes the represented default meaning; it
is an explicit experimental adaptation rather than a conformance repair.

Each adapted snapshot passes import and Core checking, fresh Ecore/XMI export,
reload, identity-map comparison, observation comparison, and a second Core
check. Regression fixtures separately cover explicit false, zero, empty String,
and first-enumeration values beside absence; repeated scalars and reciprocal
references; independent ordering at opposite ends; changed numeric identities
and containment traversal; duplicate identity maps; and inconsistent opposite
counts. A richer EMF Compare metamodel is rejected because it contains
operations. Further fixtures confirm rejection of defaults, derived features,
custom datatypes, generics, and broken references.

\subsection{Answers to the research questions}
RQ1 is answered by the declarative semantics, finite-closure argument, and
unconditional checker equivalence. RQ2 is answered by
Equation~\ref{eq:adequacy}: the independently defined source meaning agrees with
successful elaboration and acceptance under a lexical premise that contains no
model-validity assumption. RQ3 receives a narrower empirical answer: the bridge
preserves the selected observations on six explicitly adapted snapshots and one
raw control, while rejecting constructs it cannot represent faithfully.

The times in Table~\ref{tab:train} measure one checker process per fixed input on
Linux under WSL2, using an Intel i5-14400F. Import, export, and compilation are excluded,
and concurrent load was uncontrolled. They demonstrate completion at these
sizes, not comparative performance.
