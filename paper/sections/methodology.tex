\section{Formalization}


\subsection{Scope and Representation}
A \emph{schema} $S$ represents a metamodel's packages, classes, inheritance,
properties and binary associations. A finite \emph{snapshot} $M$ records objects,
their classifiers, and observations $(o,p,L)$ associating object $o$ and property
$p$ with a value list $L$. Declaration identities are typed by kind and distinct
from names. An inherited property retains its identity through a diamond.

Raw inputs can contain unresolved references, duplicate identities and repeated
observation keys. The total lookup $L_M(o,p)$ concatenates all lists at $(o,p)$,
yielding $[]$ if none match. Conformance requires exactly one applicable row:
an absent row and an explicit empty row have equal lookups but different validity.

Values are object references, Booleans, unbounded integers, XML-character-valid
strings and enumeration literals. Properties declare types, bounds, ordering,
uniqueness, opposites and composition. Packages are represented within an
implicit outer scope. A binary association may have one association-owned,
nonnavigable end; its observations record incidence rather than a navigable slot.
Operations, reflective services and default/unset histories are deferred.

\subsection{Well-formed Schemas and Conforming Snapshots}
Schema well-formedness $W(S)$ requires distinct and resolved identities, valid
names, acyclic package and inheritance graphs, consistent ownership, types,
multiplicities and association ends, and at most one identifier
property across direct and inherited declarations. This flag restriction does not impose global uniqueness on identifier values. Train's ordinary \emph{id} attribute does not have that flag. A property applies to an object through its class or an ancestor,
or as an applicable association-owned end.

Snapshot conformance $C(S,M)$ includes $W(S)$. Objects have distinct identities
and concrete resolved classifiers. Each applicable object/property pair has
exactly one observation row, a convention of our representation rather than
a requirement on physical EMOF storage. A list containing false, zero or an empty string still contains a value.

For a property $p$ with lower bound $\ell_p$ and upper bound $u_p$, conformance
requires, for every stored object to which $p$ applies, correctly typed values and
\[
 \ell_p\leq |L_M(o,p)|\ \land\
 (u_p=\ast\ \lor\ |L_M(o,p)|\leq u_p),
 \qquad \mathit{unique}_p\Rightarrow\operatorname{Nodup}(L_M(o,p)).
\]
The upper bound is either a finite natural number or unlimited ($\ast$);
list length counts occurrences. Reference equality uses object identity. Ordered observations are compared as
sequences and unordered observations up to permutation. This observation
comparison is distinct from the conformance predicate.

\paragraph{Opposites.}
An association is observed at both ends. For opposite properties $p,q$ and
objects $x,y$, the number of forward references must equal the reverse count:
\begin{equation}
 \#_{\operatorname{ref}(y)}L_M(x,p)
 = \#_{\operatorname{ref}(x)}L_M(y,q).
\label{eq:opposite}
\end{equation}
Thus a SwitchPosition occurs in \emph{Route.follows} exactly as often as that
Route occurs in \emph{SwitchPosition.route}. Counting preserves repeated links
when ends are nonunique. The CMOF Reflection rationale in MOF~13.2.5 corroborates
such links; Equation~\ref{eq:opposite} states our selected EMOF snapshot interpretation.

\paragraph{Containment.}
MOF~12.5.5 restricts an object to one container and at most one non-null
container property. We require all composite occurrences of a child to identify
one parent, and at most one explicit reverse container property to have values.
Repeated unpaired occurrences can therefore identify one parent, while two active
reverse properties violate the second restriction. Separately, no nonempty
composite path may return to its source, ensuring acyclic containment.

\subsection{Executable Checking}
The checker combines Boolean decisions for $W$ and $C$. Its proof combines
local decision/predicate equivalences with a correspondence between computed
reachability and paths. Reachability expands adjacent identities
until a fixed point within the finite carrier bound. Resolution confines paths
to that carrier; each expansion adds a fresh identity or stabilizes, and every
computed identity has a stored path.

The principal checker theorem is
\begin{equation}
 \operatorname{check}(S,M)=\mathsf{true}
 \quad\Longleftrightarrow\quad C(S,M).
\label{eq:checker}
\end{equation}
It holds for every raw schema and snapshot, including malformed inputs. There
is an analogous theorem for $W(S)$. These results establish soundness and
completeness for the defined predicates, without a runtime complexity claim.


\subsection{Symbolic Declarations and Elaboration}
Symbolic declarations let users name model elements without allocating Core
identities themselves. Parsing produces a source abstract syntax tree (AST);
elaboration resolves its names and builds the Core representation. For a source
AST $d$, we define satisfaction $\mathcal S(d)$ using paths, applicability,
typing, opposite counts and containment. This definition does not call the Core
checker, elaborator or $C$.

The elaborator $E$ checks alias uniqueness and qualification, resolves references,
allocates identities by declaration kind and list position, and translates values.
The proof transports source paths, applicability, values and containment to Core.

Let $A(d)$ require nonempty declaration and object aliases with nonempty
XML-valid components. This lexical condition is explicit because successful binding alone does not
establish all these name conditions; it does not assume model conformance.
The \emph{source adequacy theorem} states
\begin{equation}
 A(d)\Longrightarrow\left(
 \mathcal S(d)\ \Longleftrightarrow\
 \exists S,M.\ E(d)=\mathsf{ok}(S,M)\land
 \operatorname{check}(S,M)=\mathsf{true}\right).
\label{eq:adequacy}
\end{equation}
Under $A(d)$ and a successful elaboration, a separate theorem equates $\mathcal S(d)$ with
$C(S,M)$. The result concerns AST elaboration; parsing and expressibility of every raw
Core pair are separate questions.

\subsection{Interpreting the Standards}
Our audit traces the definitions to MOF~2.5.1 and adopted UML, classifying
Clause~12.4's 32 restrictions as enforced, excluded or deferred
\cite{omg_mof_251,omg_uml_25}. This exposes both interpretation choices and
the boundary of implemented support.

One consequential distinction is between the structural multiplicity $0..0$
and the positive-upper prerequisite of the reflective creation operation in
MOF~9.3.3. Applying that prerequisite to static declarations would reject properties
permitting no values. We check the two conditions separately without
implementing the creation operation. Table~\ref{tab:source-findings}
collects decisions used by the implemented semantics. Findings about defaults,
operations and XMI identifier collisions remain in the source ledger: their
analysis does not establish support for those features, and the table does not
present them as implemented results.

\subsection{Reusable Model Properties}
An upper-one opposite rules out repeated links to one target even when the
forward end is nonunique, illustrating reasoning from conformance. Suppose $C(S,M)$, a stored association has ends $(p,q)$, and the stored declaration
of $q$ has upper bound one. For stored objects $x,y$, with $q$ applicable at $y$,
the library proves
\[
 \#_{\operatorname{ref}(y)}L_M(x,p)
 =\#_{\operatorname{ref}(x)}L_M(y,q)
 \leq |L_M(y,q)|\leq 1.
\]
The bound limits repetitions per target, not the number of distinct targets.
