\section{Methodology}
\subsection{A bounded interpretation of EMOF}
The account starts from a source audit, because a mechanized predicate cannot by
itself establish that it is the right reading of a standard. The audit covers
all 32 restrictions in MOF 2.5.1 Clause 12.4 and records, for each one, whether
the selected representation enforces it, excludes the corresponding construct,
or defers it. Adopted UML material supplies the treatment of generalization and
inherited properties \cite{omg_mof_251,omg_uml_25}. The original normative and
machine-readable sources remain unchanged; discrepancies in auxiliary OCL and
repeated XML identifiers are documented rather than silently repaired.

The selected domain is structural and finite. It includes nested packages,
abstract and concrete classes, multiple inheritance, properties, binary
associations, primitive and enumeration values, multiplicity, ordering,
uniqueness, opposites, and containment. A binary association may have one
association-owned nonnavigable end; its retained observation denotes incidence,
not a reflective getter. The primitive domains are Boolean, arbitrary Integer,
and XML-valid String. Real, general structured datatypes, operations,
parameters, defaults and unset histories, derived behavior, comments, and
generic reflection are deferred.

Two interpretation choices determine the snapshot domain. Structural upper bounds
are no smaller than their lower bounds; the interval $0..0$ admits only an empty
collection, as allowed by adopted UML. Positive upper bounds are separately
required by the class-creation premises in MOF 9.3.3. The account also retains repeated occurrences on a
nonunique reference. This is a static observation model: it does not assert that
every admitted list is reachable through each reflective insertion operation.
For containment, the profile adopts the stronger occurrence-sensitive reading:
two composite occurrences that name the same child count twice, even if they
come from one slot. These choices are part of the stated profile rather than
claims about every possible reading of EMOF.

\subsection{Identity-based schemas and snapshots}
A schema $S$ is a finite collection of package, class, property, association,
enumeration, and literal declarations. Each kind has its own identity type;
names are metadata. An implicit outer package owns declarations written at the
source root. This is an unstored scope convention, not a materialized reflective
package graph or a proved embedding into one. A snapshot $M$ contains identified objects. Its finite observation
rows have the form $(o,p,L)$, where $L$ is a list of primitive, enumeration, or object
reference values. Raw records are intentionally permissive: duplicate
identities, dangling references, and duplicate observation keys can be
represented and then rejected by the semantics.

Schema well-formedness, written $W(S)$, requires unique and resolved
identities, valid names, acyclic package and inheritance graphs, valid ownership
and types, normalized multiplicities, binary end consistency, and at most one
inherited identifier property. A property applies to a class when its owning
class is an ancestor or when it is the applicable association-owned end.
Ancestor closure is deduplicated by declaration identity. In the catalog,
\emph{Book} therefore receives the one declaration \emph{Entry.key}, rather
than a new declaration constructed from its name.

Snapshot conformance, $C(S,M)$, includes $W(S)$, unique object and
observation identities, concrete resolved classifiers, and exactly one row for
each applicable object/property pair. An optional property is represented by an
empty row, which keeps absence distinct from false, zero, and the empty String.
Every occurrence has the declared type; list length satisfies multiplicity; and
a unique property has no equal values. Reference equality is object identity.
Ordered lists compare as sequences and unordered lists up to permutation, so
both retain duplicate counts.

For an association with opposite properties $p$ and $q$, let $L_M(o,p)$
be the occurrences observed for object $o$ at $p$. For every object pair
$x,y$, conformance requires
\begin{equation}
 \#_{\operatorname{ref}(y)}L_M(x,p)
 = \#_{\operatorname{ref}(x)}L_M(y,q).
\label{eq:opposite}
\end{equation}
Thus each of the two authors in Figure~\ref{fig:catalog} occurs once at the
book's \emph{authors} end and the book occurs once at the corresponding
author's \emph{books} end. Containment additionally gives each object at most
one incoming composite occurrence and forbids a nonempty composite path back to
its source. These constraints use the same occurrence lists as multiplicity and
opposites; no separate graph interpretation is introduced.

\subsection{A complete finite decision}
The definitions above quantify only over finite stores, but they use transitive
reachability for inheritance, package nesting, and containment. Reachability is
computed by expanding adjacent identities, discarding identities already seen,
and stopping after the size of the relevant carrier. Every computed identity
has a stored path. Completeness uses the well-formedness and resolution premises
that keep the relevant paths inside the finite carrier. Under these premises,
before stabilization each further expansion must
add a fresh carrier identity, so no path endpoint can remain undiscovered after
that many iterations. An early fixed-point optimization is proved to return the
same closure.

The executable schema and snapshot checks are Boolean conjunctions of these
finite obligations. Their correctness statements are unconditional over the raw
representation:
\begin{equation}
 \operatorname{check}(S,M)=\mathsf{true}
 \quad\Longleftrightarrow\quad C(S,M),
\label{eq:checker}
\end{equation}
with an analogous equivalence for $W(S)$. The diagnostic interface reports
the failed conjuncts; it does not claim to compute a minimum repair. A further
library result illustrates reuse: if the opposite of $p$ has upper bound one,
Equation~\ref{eq:opposite} bounds each $p$-to-object pair count by one, without
adding uniqueness to $p$.

\subsection{Independent source meaning and elaboration}
The symbolic source document $d$ uses qualified aliases for declarations and
objects. Its satisfaction relation, $\mathcal S(d)$, is defined directly over
those aliases with inductive path relations, source-level applicability,
occurrence typing, opposite counts, and containment. It does not call the Core
checker, elaborator, or $C$. This independence makes a preservation result
informative rather than definitional.

Elaboration $E$ validates global alias uniqueness and qualification, resolves
every symbolic reference, allocates a per-kind identity at each list position,
and translates observation values. The proof relates each source declaration
to its allocated identity, then transports superclass reachability,
applicability, list length, equality, duplicate freedom, permutation, pair
counts, and containment paths. For the catalog, this is why
\texttt{Book::authors} and each \texttt{Author::books} row still describe the
same two endpoint pairs after names have disappeared from semantic lookup.

Let $A(d)$ require every declaration and object alias to be nonempty, with
nonempty components containing XML-valid characters. The binder enforces the
nonemptiness conditions; source satisfaction also imposes character validity. It contains no conformance assumption. The
main connection is
\begin{equation}
 A(d)\Longrightarrow\left(
 \mathcal S(d)\ \Longleftrightarrow\
 \exists S,M.\ E(d)=\mathsf{ok}(S,M)\land
 \operatorname{check}(S,M)=\mathsf{true}\right).
\label{eq:adequacy}
\end{equation}
The forward direction includes successful elaboration. The reverse direction
reflects every conformance field through the actual successful bindings. A
fixed-result form equates $\mathcal S(d)$ directly with $C(S,M)$ when the
exhibited elaboration succeeds.

The source language allocates consecutive identities and always supplies display
names, whereas raw Core records can use arbitrary identities and unnamed
declarations. Equation~\ref{eq:adequacy} therefore characterizes the actual
source route; it does not say that every conforming raw Core record is literally
an elaboration result. A conditional reifier is available when a suitable alias
assignment, source satisfaction, and structural round-trip equalities are
supplied; existence of such assignments for all conforming Core records is not proved. The theorem begins at the AST, leaving parser correctness
to the tool boundary considered next.
