\subsection{Scope and Representation}
We formalize packages, classes with multiple inheritance, properties, binary
associations, and finite object snapshots. Values include Boolean, arbitrary
Integer, XML-valid String and enumeration literals. Properties have multiplicity,
ordering, uniqueness, opposite and containment constraints. One association end
may be association-owned and nonnavigable; its values then record incidence.
Operations, reflection, defaults/unset histories and richer datatypes are deferred.

A \emph{schema} $S$ records these declarations. Each declaration has a typed
identity distinct from its name. A \emph{snapshot} $M$ records objects, their
classifiers, and observation rows $(o,p,L)$: object $o$ has the list of values
$L$ at property $p$. We write this list as $L_M(o,p)$. In the Train example,
\emph{Route.requires} identifies a declaration and its observation contains
references to two Sensor objects. Inherited properties retain their declaration
identity, so a diamond does not create two copies of the same property.

The records admit malformed data, including duplicate identities, unresolved
references and repeated observation keys; the predicates reject them. The outer
scope is implicit, rather than a stored reflective package graph.

\subsection{Well-formed Schemas and Conforming Snapshots}
Schema well-formedness $W(S)$ requires distinct and resolved identities, valid
names, acyclic package and inheritance graphs, consistent ownership, types,
multiplicities and association ends, and at most one inherited identifier
property. A property applies to an object through its class or an ancestor,
or as an applicable association-owned end.

Snapshot conformance $C(S,M)$ includes $W(S)$. Objects have distinct identities
and concrete resolved classifiers. Each applicable object/property pair has
exactly one observation row. An empty list records zero values; it differs from
an absent row and from lists containing false, zero or the empty String.

For a property $p$ with lower bound $\ell_p$ and upper bound $u_p$, conformance
requires correctly typed values and
\[
 \ell_p\leq |L_M(o,p)|\ \land\
 (u_p=\ast\ \lor\ |L_M(o,p)|\leq u_p),
 \qquad \mathit{unique}_p\Rightarrow\operatorname{Nodup}(L_M(o,p)).
\]
Reference equality uses object identity. Ordered observations are compared as
sequences and unordered observations up to permutation. This observation
comparison is distinct from the conformance predicate.

\paragraph{Opposites.}
An association is observed at both ends. For opposite properties $p,q$ and
objects $x,y$, the number of forward references must equal the reverse count:
\begin{equation}
 \#_{\operatorname{ref}(y)}L_M(x,p)
 = \#_{\operatorname{ref}(x)}L_M(y,q).
\label{eq:opposite}
\end{equation}
Thus a SwitchPosition occurs in \emph{Route.follows} exactly as often as that
Route occurs in \emph{SwitchPosition.route}. Counting preserves repeated links
when ends are nonunique. The CMOF Reflection rationale in MOF~13.2.5 corroborates
such links; Equation~\ref{eq:opposite} states our selected EMOF snapshot interpretation.

\paragraph{Containment.}
MOF~12.5.5 gives two distinct restrictions: an object has at most one container,
and at most one container property is non-null. We therefore require that all
composite observations of a child identify the same parent, and that at most
one of its explicit reverse container properties has values. Repeated unpaired
occurrences may identify one parent; two active reverse properties still violate
the second restriction. Finally, no nonempty composite path may return to its
source. These conditions distinguish parent identity, property identity and
acyclicity.

\subsection{Executable Checking}
The checker decides each obligation. Reachability expands adjacent identities
until a fixed point within the finite carrier bound. Resolution confines paths
to that carrier; each expansion adds a fresh identity or stabilizes, and every
computed identity has a stored path.

The principal checker theorem is
\begin{equation}
 \operatorname{check}(S,M)=\mathsf{true}
 \quad\Longleftrightarrow\quad C(S,M).
\label{eq:checker}
\end{equation}
It holds for every raw schema and snapshot, including malformed inputs. There
is an analogous theorem for $W(S)$. These results establish soundness and
completeness for the defined predicates, without a runtime complexity claim.
The diagnostic interface names failed obligations; it does not compute a
minimum repair.

\subsection{Symbolic Declarations and Elaboration}
Users write qualified aliases rather than numeric Core identities. For a source
AST $d$, we define satisfaction $\mathcal S(d)$ using paths, applicability,
typing, opposite counts and containment. This definition does not call the Core
checker, elaborator or $C$.

The elaborator $E$ checks alias uniqueness and qualification, resolves references,
allocates identities by declaration kind and list position, and translates values.
The proof transports source paths, applicability, values and containment to Core.

Let $A(d)$ require nonempty declaration and object aliases with nonempty
XML-valid components. This is a lexical condition, not a conformance premise.
The \emph{source adequacy theorem} states
\begin{equation}
 A(d)\Longrightarrow\left(
 \mathcal S(d)\ \Longleftrightarrow\
 \exists S,M.\ E(d)=\mathsf{ok}(S,M)\land
 \operatorname{check}(S,M)=\mathsf{true}\right).
\label{eq:adequacy}
\end{equation}
The forward direction constructs elaboration; the reverse recovers satisfaction.
For a successful elaboration, a separate theorem equates $\mathcal S(d)$ with
$C(S,M)$. Clients can reuse these bindings, but the result excludes parsing and
does not assert that every raw Core pair is expressible in the DSL.

\subsection{Reusable Model Properties}
Suppose $C(S,M)$, a stored association has ends $(p,q)$, and the stored declaration
of $q$ has upper bound one. For stored objects $x,y$, with $q$ applicable at $y$,
the library proves
\[
 \#_{\operatorname{ref}(y)}L_M(x,p)
 =\#_{\operatorname{ref}(x)}L_M(y,q)
 \leq |L_M(y,q)|\leq 1.
\]
Opposite consistency and reverse multiplicity exclude repeated links to one
target, even without forward uniqueness. This limits repetitions per target,
not the number of targets.

Let $T_{o,p}(M)$ negate Boolean occurrences at key $(o,p)$, retaining all other
values and rows. Empty, missing and non-Boolean slots are unchanged. We prove
\begin{equation}
 C(S,M)\Longrightarrow C(S,T_{o,p}(M)).
 \label{eq:toggle}
\end{equation}
Injective negation preserves typing, lengths and uniqueness. Unchanged keys and
references preserve opposites, containers and reachability. The proof reconstructs
every conformance field without a post-edit validity premise or check. Two toggles
restore even a malformed raw snapshot.

A present \emph{Route.active} value can thus change without structural rechecking.
This need not preserve SwitchSet, which depends on entry semaphores and switch
positions. Relinking, repair and reflective execution require separate results.
