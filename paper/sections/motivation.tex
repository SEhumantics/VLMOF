\section{Motivation}
The Train Benchmark provides a published railway metamodel, model generators
and domain queries \cite{szarnyas_etal_2018}. We select its route--switch-position
structure as a small modeling-language case. The original artifact describes the
metamodel in Xcore; our executable notation is a separately attributed
translation. Neither that translation nor the small authored snapshot below is
an original Train input or evidence of a production railway system.

Figure~\ref{fig:train} retains two opposite pairs and a required sensor
multiplicity. Its source Xcore includes:
\begin{verbatim}
contains SwitchPosition[] follows opposite route
refers Sensor[2..*] requires
\end{verbatim}
These Route declarations use Xcore syntax. The inverse route has upper bound
one. The projection retains RailwayElement and TrackElement inheritance,
Boolean and Integer attributes, and Position's three literals. Containers,
regions, segments and semaphores are omitted and documented in the artifact.

Consider one route, one switch, one switch position and two sensors. Removing
one required sensor violates the lower bound. Removing only the position's
reverse route value breaks opposite consistency while preserving local upper
bounds. This represented inconsistency need not be reachable through an
inverse-maintaining editor.

Reciprocity and an upper-one reverse bound also prohibit repeated forward
references to one target, even without forward uniqueness. Train explicitly
requires uniqueness; a separate nonunique example isolates the theorem's
premises. Unpaired composite occurrences can repeat with one parent identity,
whereas two paired composite features can activate two forbidden container
roles. These distinctions motivate a foundation before a tool comparison.

The implemented VL-MOF translation includes the following route object:
\begin{minipage}{\linewidth}
\begin{verbatim}
object route : railway::Route {
  observe railway::RailwayElement::id = [101];
  observe railway::Route::active = [true];
  observe railway::Route::follows = [@switchPosition];
  observe railway::Route::requires = [@sensorA, @sensorB];
}
\end{verbatim}
\end{minipage}
Qualified names identify declarations, \texttt{@} denotes references, and lists
retain occurrences. Scalars are singleton lists; absence is empty. The complete
example supplies the other objects and inverse rows, without implicit completion.
Default-sensitive scalar values are explicit.

The inherited \emph{id} is ordinary Integer data: equal values on distinct
objects are structurally admissible. Train's SwitchSet query additionally uses
route activity, entry-semaphore state and switch-position agreement. The
projection omits semaphores and does not evaluate that domain query.
